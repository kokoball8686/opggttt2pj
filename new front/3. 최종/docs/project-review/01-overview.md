# 프로젝트 리뷰 요약

## 1. 결론

이 프로젝트는 기능적으로는 동작하는 웹앱이며, Next.js App Router 기반으로 전환하려는 의도와 구조 정리 작업이 일부 반영되어 있다. 하지만 여전히 여러 면에서 현업 수준의 엔지니어링 품질을 갖추지 못했다.

핵심은 다음과 같다.

- 기능은 작동한다.
- 구조는 일부 정리되었다.
- 하지만 Next.js의 핵심 패턴을 제대로 활용하지 못했다.
- 전역 스타일, 클라이언트 중심 페이지, 컴포넌트 책임 분리 부족이 여전히 남아 있다.
- 면접에서 구조적 질문을 받으면 약한 지점을 매우 쉽게 드러낼 수 있다.

즉, 이 프로젝트는 "데모 수준의 동작 가능 상태"라고 평가할 수는 있지만, "현업 수준의 아키텍처 설계"라고 보기는 어렵다.

## 2. 전체 평판

### 장점

- App Router 구조를 일부 도입했다.
- API route와 lib를 분리하려는 의도가 있다.
- 여러 컴포넌트 파일이 이미 존재한다.
- 상태 관리와 데이터 로딩을 일부 Hook로 추상화했다.
- Recharts와 Framer Motion을 실제로 사용하려는 시도가 있었다.

### 문제점

- 페이지 대부분이 client component로 구현되어 있다.
- 전역 CSS가 너무 커서 유지보수성이 낮다.
- 페이지 컴포넌트가 너무 큰 책임을 맡고 있다.
- 스타일, 레이아웃, 데이터 로직, 차트 로직이 서로 섞여 있다.
- Tailwind는 원래 의도했던 스타일 전략이었지만, 실제 구현 단계에서 빠르게 지나치면서 거의 사용되지 않은 상태다.
- 즉, Tailwind 미사용은 설계 실수라기보다 구현 누락/기술 부채에 가깝다.
- 앞으로는 Tailwind를 기본 스타일 시스템으로 정하고, CSS를 전역 적층으로 남기지 않는 방향으로 정리해야 한다.
- Next.js의 서버 컴포넌트 장점을 거의 살리지 못했다.

## 3. 가장 중요한 한 줄 결론

이 프로젝트는 "기능 구현은 되었지만, 구조적으로는 아직 프레임워크의 의도에 맞게 설계되지 않은 상태"다.

---

## 4. 왜 이 프로젝트가 면접에서 약하게 보이는가

면접관이 코드를 볼 때 가장 먼저 보는 건 단순히 "동작하느냐"가 아니라 "설계가 어떤가"이다. 이 프로젝트는 기능적으로는 흥미롭고 작동하지만, 구조를 보고 다음 같은 질문을 떠올리기 쉽다.

- 서버와 클라이언트의 경계를 제대로 분리했는가?
- 각 페이지가 어떤 책임을 가지는가?
- 공통 UI가 컴포넌트로 재사용되는가?
- CSS가 전역으로 과도하게 퍼져 있는가?
- Tailwind를 의도하고 설치했는가, 아니면 그냥 남겨둔 것인가?
- 데이터 로직과 UI 로직이 잘 분리되었는가?

이 질문들에 대해 현재 프로젝트는 답이 약하다.

## 5. 현 상태의 큰 그림

지금까지의 프로젝트는 다음 흐름으로 이해할 수 있다.

1. 기존 정적 구조를 Next.js 구조로 전환하려는 시도
2. 일부 라우트와 컴포넌트를 추가
3. Recharts/Framer Motion을 활용하려는 시도
4. 로딩과 에러 상태를 일부 개선
5. 그러나 전체 설계는 여전히 빠른 구현 중심으로 갈라졌다.

이것은 "실행 가능한 프로토타입"으로는 충분히 좋지만, 현업 구조 기준으로는 아직 미완성이다.

## 6. 평가 요약

- 기능 구현력: 보통 이상
- 구조 설계: 중하
- Next.js 이해도: 보통
- 유지보수성: 낮음
- 면접용 완성도: 보통 이하

---

## 7. 핵심 메시지

이 프로젝트는 "완전히 무너진 코드"는 아니다. 그러나 "현업 기준으로 보면 아직 구조 정리 단계"다.

면접이나 코드 리뷰에서 지적받기 쉬운 포인트를 막아야 한다면, 다음 3가지가 우선이다.

1. 클라이언트 페이지 비중 축소
2. 전역 CSS 분리/모듈화
3. 페이지와 컴포넌트 책임의 명확화

이 세 가지가 가장 중요하다.
