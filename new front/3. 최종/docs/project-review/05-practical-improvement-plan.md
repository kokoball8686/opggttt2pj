# 실무적 개선 계획

## 1. 현재 프로젝트의 현실적인 평가

이 프로젝트는 다음 단계에 있다.

- 기능 구현은 완료된 편이다.
- 구조 정리도 어느 정도 진행되었다.
- 하지만 현업급 설계 기준으로 보면 아직 부족하다.

즉, "점프가 아니라 계속 정리 중인 단계"다.

## 2. 무엇이 가장 먼저 개선돼야 하는가

가장 우선순위가 높은 항목은 세 가지다.

1. 클라이언트 페이지 비중 축소
2. 전역 CSS 구조 정리
3. 페이지 책임 분리

이 세 가지가 지켜지면, 프로젝트 품질이 훨씬 좋아진다.

## 3. 우선순위 1: 클라이언트 컴포넌트 비중 축소

### 목표

- 페이지 대부분을 서버 컴포넌트로 두기
- 데이터 fetch는 서버 계층에서 처리
- 상호작용이 필요한 요소만 client component로 남기기

### 적용 예시

- page.tsx: 서버 컴포넌트로 만들기
- 내부 UI 조립만 client component로 분리
- useMatches처럼 데이터 패칭은 server layer로 이동 가능

### 효과

- 초기 렌더링 향상
- Next.js의 장점 활용
- 캐시 전략 가능
- 면접에서 더 설계적으로 보임

## 4. 우선순위 2: 전역 CSS 축소

### 현재 문제

- [src/app/globals.css](../../src/app/globals.css) 가 너무 큼
- 모든 스타일이 전역화되어 있음
- 디자인 시스템이 불명확함

### 목표

- globals.css는 reset, 토큰, 기본 스타일 정도만 유지
- 특정 UI 컴포넌트는 컴포넌트별 style 또는 CSS module로 분리
- Tailwind 도입 여부를 명확히 결정

### 목적

- 스타일 충돌 감소
- 재사용성 증가
- 유지보수성 증가

## 5. 우선순위 3: 페이지 책임 분리

### 현재 문제

- [src/app/page.tsx](../../src/app/page.tsx) 가 비대함
- 비즈니스 로직과 화면 조립이 섞여 있음

### 목표

- page.tsx는 레이아웃 조립용으로 축소
- 여러 작은 섹션 컴포넌트로 분리
- 계산 로직은 lib/stats로 남기기
- 데이터 로딩은 hook 또는 서버 계층으로 이동

### 기대 효과

- 테스트 용이
- 디버깅 용이
- 코드리뷰 용이
- 수정 범위 축소

## 6. Tailwind는 필수 도입 항목이다

### 현재 상태

Tailwind가 설치되어 있으나 거의 사용되지 않는다. 그러나 이건 설계상 의도 누락일 뿐이며, 원래는 Tailwind를 기본 스타일 전략으로 두고 시작한 프로젝트였다.

즉, 지금의 문제는 "Tailwind를 안 쓰고 있다"가 아니라, "Tailwind를 실제로 정착시키지 못했다"는 점이다.

### 결정 사항

1. Tailwind는 선택지가 아니라 기본 규칙으로 유지한다.
2. 전역 CSS는 reset, 토큰, 베이스 스타일 수준으로만 남긴다.
3. 컴포넌트와 페이지 레이아웃은 Tailwind utility로 구성한다.
4. 기존 custom CSS는 점진적으로 정리하면서 Tailwind로 이전한다.

### 추천

이 프로젝트는 Tailwind를 완전히 버리는 선택을 할 수 없으며, 오히려 지금부터는 Tailwind를 중심으로 구조를 재편하는 것이 맞다.

이유는 단순하다. 이미 어느 정도 기능이 완성되어 있어도, 스타일 전략이 전역 CSS 중심으로 남아 있으면 코드 유지보수성과 확장성이 낮아지기 때문이다.

즉, “점진적 전환”이 아니라 “Tailwind 표준화”가 현재의 기준점이다.

## 7. 가장 안전한 현실적 액션플랜

### 1단계: 구조 정리

- page.tsx에서 덩치 큰 섹션을 컴포넌트로 분리
- 공통 스타일만 남기기
- 데이터 계산 로직 정리

### 2단계: 서버/클라이언트 경계 정리

- 필요한 페이지만 client component로 유지
- 나머지는 서버 컴포넌트로 전환

### 3단계: 스타일 일관화

- globals.css 축소
- 컴포넌트별 CSS 분리
- Tailwind를 기본 스타일 시스템으로 확정
- 기존 custom CSS를 Tailwind utility로 점진 이전

### 4단계: 검증

- lint
- build
- route별 동작 확인
- 브라우저에서 주요 화면 검증

## 8. 면접에 사용할 설명 문장

다음 문장은 프로젝트를 현실적으로 설명하는 데 좋다.

> “기능 구현은 빠르게 진행했지만, 구조적으로는 아직 서버/클라이언트 경계와 스타일 시스템 정리가 완료되지 않은 상태입니다. 특히 Tailwind는 원래 의도했던 기술 스택이었으나 실제 구현에서 빠르게 누락되었고, 앞으로는 이를 기본 스택으로 정리해야 합니다. 지금은 기능 동작을 우선시한 구현 단계였고, 이후 아키텍처와 스타일 표준화를 정리하는 단계로 넘어가야 합니다.”

이 문장은 약점을 인정하면서도, 향후 개선 방향을 명확히 제시한다.

## 9. 최종 결론

이 프로젝트는 기능적으로는 꽤 완성도가 높지만, 설계적으로는 아직 아키텍처 정리가 필요한 상태다. 같은 문서들의 핵심 메시지는 모두 동일하다.

- 페이지가 너무 큼
- 클라이언트 중심 비중이 높음
- 전역 CSS가 과함
- Tailwind 의도는 있었지만 실행이 미흡함
- 구조 분리가 아직 완전하지 않음

이 문제를 정리하고 난 뒤에는, 이 프로젝트를 “기능 중심 데모”에서 “설계-conscious 프로젝트”로 만드는 작업이 가능하다.

이것이 현재 가장 현실적인 개선 방향이다.
